# Session 022 — Two-Way Sync Safety

**Date**: 2026-10-21

## Context

An analysis (outside this repository) checked whether the image can serve
as a safe two-way bridge between Obsidian Sync and GitHub: edits on any
Obsidian device reach GitHub, and edits pushed to GitHub (for example by an
AI assistant) flow back into Obsidian. Experiments against the unmodified
code reproduced silent loss of GitHub edits (`-X ours`), repositories stuck
mid-merge, edits lost when a rebase was aborted or interrupted, `/vault`
being wiped on first start, and silent failures. This session fixes them on
branch `fix/two-way-sync-safety`, red-green where possible.

## What was accomplished

- **Test suite** (`tests/`, ADR-0024): Docker-based unit tests for the git
  functions (moved to `rootfs/usr/local/lib/git-sync-functions.sh`) and
  container tests with a stub `ob`. 18 files, 146 checks, about 2 minutes.
- **Pull strategy** (ADR-0021, supersedes ADR-0016's conflict handling):
  file-by-file integration with `(git conflict <date> <time> UTC)` copies,
  never a rebase/merge state in the vault.
- **Failure handling**: `git add` errors reported, stale `index.lock`
  removed at start, interrupted rebase/merge refused by both the watcher and
  init-config (container stops before ob sync starts), a failed periodic pull
  no longer kills the watcher, shutdown waits for a running cycle.
- **Health** (ADR-0022): `/config/health` plus `HEALTHCHECK`; a pull/push
  once at watcher start.
- **obsidian-headless** (ADR-0023): 0.0.14; state in `/config/xdg`; after a
  fresh clone, files get their own last-commit time and stale `state.db` is
  removed; no cloning over a non-empty `/vault`.
- **Settings**: empty `OBSIDIAN_GIT_SYNC_CONFIGS`/`FILE_TYPES` means none
  (with a warning); new `OBSIDIAN_GIT_SYNC_CONFLICT_STRATEGY`.
- **Compose/Unraid**: 30-second stop grace period, `/vault` required.
- **inotify**: stderr no longer goes into the event FIFO.

Every behavioural fix has a test that failed before the change; commit
messages name the red check. The headless bump was checked by confirming
all flags used still exist.

## Corrections to the earlier analysis

- The shutdown push is **not** cut off by s6 after 3 seconds:
  `S6_SERVICES_GRACETIME` applies only to legacy `services.d` services, and
  s6-rc waited for an 8-second push (`tests/container/shutdown.sh`). Docker's
  default 10-second stop timeout is the real limit (reproduced with a
  12-second push).

## Subagent reviews

### Linux expert
- Bare `do_periodic_pull` under `set -e` killed the watcher on any pull
  failure (regression from this session) — **fixed**.
- `.gitignore`d remote files deleted by the merge commit — **fixed**.
- Check-then-overwrite window with concurrent ob writes — **narrowed**
  (re-check right before rename/delete).
- Folder replaced by file moved the file into the folder — **fixed**; also
  found `_blob_at` returning tree ids.
- Unapplicable paths blocked all pulls/pushes — **fixed** (logged, merge
  recorded).
- Inconsistent filters in the Markdown merge — **fixed**.
- Conflict copies overwriting each other — **fixed** (suffix).
- Trap re-entry mid-cycle — **fixed** (deferred shutdown).
- `touch` following symlinks as root — **fixed** (`-h`).
- `lost+found` rejected — **fixed** (removed if empty).
- Busy watcher turning unhealthy — **fixed**.
- `S6_SERVICES_GRACETIME` needed — **rejected**, disproved by test (see
  above).
- `/config` not writable — **rejected**: `init-usermap.sh` already chowns
  `/config` to PUID:PGID.

### Obsidian expert
- Same commit time for all cloned files let stale notes win — **fixed**
  (per-file times).
- Initial sync resurrects deletions — **documented** (README, ADR-0023).
- `.obsidian` conflict copies synced to every device — **fixed** (no copy).
- Conflict copies in Dataview/Tasks — **documented**.
- Race before rename — **narrowed** (as above).
- `.base` and `.MD` merging — **added**.
- Plugins rewriting `data.json` often (commit churn) — not addressed.
- Auth token location moves with `XDG_CONFIG_HOME` — no impact: the image
  always passes `OBSIDIAN_AUTH_TOKEN`.

### UX designer
- Unraid template: `/vault` required, stop timeout — **fixed**.
- "GitHub" hard-coded — **fixed** ("git", remote branch named in logs).
- Upgrade path for users who mounted an existing vault — **documented**,
  log message names the cause.
- Interrupted-operation hint for named volumes — **fixed**.
- Conflict strategy vs git conflicts — **documented**.
- Empty-means-none surprises — **warning logged**.
- UTC in copy names, health reasons, inspect command, dev prerequisites —
  **fixed**.

## Not verified
